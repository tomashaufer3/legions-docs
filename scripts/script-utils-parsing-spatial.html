TL;DR

Assigns a court district (soudní okres / Gerichtsbezirk) to any point given in WGS84 lon/lat, by locating it inside the MPIDR / Rumpler-Seger 1910 court polygons (reference/places/mpidr/…v.1.0.shp). This is the finer juridical layer the name-based okres matcher (utils.parsing.records_geo) cannot resolve — a court is a sub-okres unit, so it can only be fixed geometrically.

How it works

Why pure numpy (no geopandas / pyshp / pyproj)

Consistent with utils.parsing.districts (which hand-reads the .dbf), this module avoids a heavy geo stack:

  • a minimal ESRI shapefile reader for polygon records (shape type 5) — record order aligns 1-to-1 with the .dbf rows (districts.read_dbf), so each polygon inherits ID_1 (=court_id) and its parent REGION/DISTRICT (=okres);
  • a closed-form ellipsoidal LAEA forward projection (GRS80, EPSG:3035, the .shp CRS) to turn lon/lat into the projected metres the polygons live in;
  • ray-casting point-in-polygon with a bounding-box prefilter.

Validation: of the settlements carrying both a court and a name-based okres_id, the court's okres agrees with the name 90.0 % of the time on containment alone (build of 2026-09-23) and ~96 % after the D-35 near-miss repair — which agrees by construction on the rows it snaps, so the QA gate counts those rows as the disagreements they were (audit 2026-09-22 §B9). The 68 % first measured on 2026-07-16 was not structural, as this note once claimed: it was a coordinate bug — a third of geocodes came from an unguarded unique-name fallback (audit 2026-07-16 §D2). Treat court_id as a complementary juridical layer; the analysis-grade okres key remains the name-based okres_id.

.. warning:: Until 2026-08-05 this note also claimed that central-Prague coordinates "correctly land in the separate 1910 okresy Královské Vinohrady / Nusle / Vršovice, not okres Praha — verified". That was wrong, and it hid a defect for three weeks. Staré Město was inside the 1910 city; the reason the coordinate landed in Vinohrady is that the MPIDR polygon for Prague — the right size, 20.8 km² against ~21 km² — has its eastern edge drawn some 500 m too far west. A generalisation artefact had been written down as expected behaviour, which is the most expensive kind of comment there is: every later reader who checked stopped checking. See SNAP_TOL_M and CourtLocator.locate_snapped for the repair, and D-35.

def laea_forward(lon, lat):
    """WGS84 lon/lat (degrees) → EPSG:3035 (ETRS89-LAEA) x/y in metres.

    Ellipsoidal Lambert Azimuthal Equal-Area, oblique aspect (Snyder 1987, eqs. 24-16 ff.),
    vectorised. Accepts scalars or arrays.
    """
    lon = np.radians(np.asarray(lon, dtype="f8"))
    lat = np.radians(np.asarray(lat, dtype="f8"))

    def _q(phi):
        s = np.sin(phi)
        return (1 - _E2) * (s / (1 - _E2 * s * s)
                            - (1 / (2 * _E)) * np.log((1 - _E * s) / (1 + _E * s)))

    qp = _q(np.pi / 2)
    rq = _A * np.sqrt(qp / 2)
    beta = np.arcsin(np.clip(_q(lat) / qp, -1, 1))
    beta0 = np.arcsin(np.clip(_q(_LAT0) / qp, -1, 1))
    m0 = np.cos(_LAT0) / np.sqrt(1 - _E2 * np.sin(_LAT0) ** 2)
    d = _A * m0 / (rq * np.cos(beta0))
    dl = lon - _LON0
    b = rq * np.sqrt(2 / (1 + np.sin(beta0) * np.sin(beta)
                          + np.cos(beta0) * np.cos(beta) * np.cos(dl)))
    x = b * d * np.cos(beta) * np.sin(dl)
    y = (b / d) * (np.cos(beta0) * np.sin(beta)
                   - np.sin(beta0) * np.cos(beta) * np.cos(dl))
    return _FE + x, _FN + y

def read_polygons(shp_path) -> list[list[np.ndarray]]:
    """Read an ESRI ``.shp`` into one entry per record (record order = ``.dbf`` row order).

    Each entry is a list of rings; each ring is an ``(N, 2)`` float array of projected
    coordinates. Non-polygon / null records yield an empty list.
    """
    raw = Path(shp_path).read_bytes()
    pos, n = 100, len(raw)                       # skip the 100-byte file header
    recs: list[list[np.ndarray]] = []
    while pos < n:
        _rec_no, clen = struct.unpack(">ii", raw[pos:pos + 8])
        pos += 8
        nxt = pos + clen * 2                      # content length is in 16-bit words
        shape_type = struct.unpack("<i", raw[pos:pos + 4])[0]
        if shape_type != 5:                       # 5 = polygon; 0 = null / other
            recs.append([])
            pos = nxt
            continue
        p = pos + 4 + 32                          # skip shape type (4) + bbox (4 doubles)
        n_parts, n_pts = struct.unpack("<ii", raw[p:p + 8])
        p += 8
        parts = struct.unpack("<%di" % n_parts, raw[p:p + 4 * n_parts])
        p += 4 * n_parts
        pts = np.frombuffer(raw[p:p + 16 * n_pts], dtype="<f8").reshape(n_pts, 2)
        idx = list(parts) + [n_pts]
        recs.append([pts[a:b] for a, b in zip(idx[:-1], idx[1:])])
        pos = nxt
    return recs

class CourtLocator:
    """Locate WGS84 points inside the MPIDR Czech-lands court polygons.

    Builds an in-memory list of ``(court_id, okres_code, rings, bbox)`` from the aligned
    ``.dbf`` / ``.shp`` pair, filtered to the Czech crown lands. :meth:`locate` returns the
    ``(court_id, okres_code)`` of the polygon containing a point, or ``(None, None)``.
    """

    def __init__(self, dbf_path, shp_path, lands: set[str] = _CZECH_LANDS):
        dbf = read_dbf(dbf_path)
        polys = read_polygons(shp_path)
        if len(dbf) != len(polys):
            raise ValueError(f".dbf ({len(dbf)}) and .shp ({len(polys)}) record counts differ; "
                             "cannot align attributes to geometry.")
        self.courts: list[tuple] = []
        self.by_okres: dict[int, list[tuple]] = {}
        for rec, rings in zip(dbf, polys):
            if rec.get("LAND") not in lands or not rings:
                continue
            allpts = np.vstack(rings)
            bbox = (allpts[:, 0].min(), allpts[:, 1].min(),
                    allpts[:, 0].max(), allpts[:, 1].max())
            code = f"{rec['REGION']}-{rec['DISTRICT']}"
            entry = (int(rec["ID_1"]), code, rings, bbox)
            self.courts.append(entry)
            oid = int(rec["REGION"]) * 1000 + int(rec["DISTRICT"])
            self.by_okres.setdefault(oid, []).append(entry)

    def locate(self, px: float, py: float) -> tuple:
        """Return ``(court_id, okres_code)`` for a projected point, else ``(None, None)``.

        Containment is **even-odd over all rings** (odd ring count = inside): an ESRI
        polygon's holes are extra rings, so a point inside an enclave (a city court cut
        out of the surrounding rural court) tests inside the outer ring *and* the hole —
        even parity, correctly outside. A plain ``any()`` would let whichever polygon
        comes first in file order claim enclave points.
        """
        for court_id, okres_code, rings, (x0, y0, x1, y1) in self.courts:
            if not (x0 <= px <= x1 and y0 <= py <= y1):
                continue
            if sum(_point_in_ring(px, py, r) for r in rings) % 2 == 1:
                return court_id, okres_code
        return None, None

    def locate_snapped(self, px: float, py: float, prefer_okres: int | None,
                       tol_m: float = SNAP_TOL_M) -> tuple:
        """:meth:`locate`, but a near miss against *prefer_okres* is pulled back into it.

        Returns ``(court_id, okres_code, snapped)``.

        The MPIDR outlines are an empire-wide generalisation, so a city border can sit a
        kilometre from where it ran. Prague is the case that made this necessary: the
        polygon labelled *Prag/Praha St.* is the right size (20.8 km² against the city's
        ~21 km²) but its eastern edge is drawn ~500 m too far west, so the single Wikidata
        coordinate every ``Praha`` birth carries — Old Town Square, 50.0875 N 14.4214 E,
        unambiguously inside the 1910 city — fell into neighbouring Královské Vinohrady.
        All 2,691 court-placed Prague births went there and the Praha court polygon
        received **none**.

        The repair only fires where the name evidence and the geometry disagree *and* the
        point is within ``tol_m`` of the named okres — the signature of a boundary drawn
        slightly wrong. A disagreement further out is a disagreement about which place this
        is, not about where a line runs, and is left standing so the layer keeps its value
        as a cross-check. Snapped rows are flagged, so any use of the court layer as
        independent evidence can drop them.
        """
        court_id, okres_code = self.locate(px, py)
        if prefer_okres is None or pd.isna(prefer_okres):
            return court_id, okres_code, False
        prefer_okres = int(prefer_okres)
        if okres_code is not None:
            r, d = okres_code.split("-")
            if int(r) * 1000 + int(d) == prefer_okres:
                return court_id, okres_code, False        # geometry already agrees

        best, best_d = None, tol_m
        for entry in self.by_okres.get(prefer_okres, []):
            _cid, _code, rings, (x0, y0, x1, y1) = entry
            if not (x0 - tol_m <= px <= x1 + tol_m and y0 - tol_m <= py <= y1 + tol_m):
                continue
            dist = min(_ring_min_distance(px, py, r) for r in rings)
            if dist <= best_d:
                best, best_d = entry, dist
        if best is None:
            return court_id, okres_code, False
        return best[0], best[1], True

def add_court_ids(df: pd.DataFrame, locator: CourtLocator,
                  lat_col: str = "lat", lon_col: str = "lon",
                  prefix: str = "", okres_col: str | None = None,
                  tol_m: float = SNAP_TOL_M) -> pd.DataFrame:
    """Append ``{prefix}court_id`` (Int64) and ``{prefix}okres_code`` from a spatial lookup.

    Rows with a missing coordinate — or points outside every Czech-lands court polygon —
    get ``<NA>``. Distinct coordinate pairs are located once and broadcast.

    Pass *okres_col* — the row's own name-derived okres id — to enable the near-miss repair
    described in :meth:`CourtLocator.locate_snapped`; a boolean ``{prefix}court_snapped``
    then records which rows it moved. Without it the lookup is pure containment, as before.
    """
    out = df.copy()
    has = out[lat_col].notna() & out[lon_col].notna()
    cid = pd.array([pd.NA] * len(out), dtype="Int64")
    ocode: list[object] = [pd.NA] * len(out)
    snapped = np.zeros(len(out), bool)
    prefer = out[okres_col].to_numpy() if okres_col and okres_col in out.columns else None
    if has.any():
        sub = out.loc[has, [lon_col, lat_col]]
        xs, ys = laea_forward(sub[lon_col].to_numpy(), sub[lat_col].to_numpy())
        # cache by rounded coordinate *and* preferred okres: the same point can legitimately
        # resolve differently for two settlements whose names put them in different okresy
        cache: dict[tuple, tuple] = {}
        pos = np.flatnonzero(has.to_numpy())
        for k, px, py in zip(pos, xs, ys):
            want = None if prefer is None or pd.isna(prefer[k]) else int(prefer[k])
            key = (round(float(px), 1), round(float(py), 1), want)
            hit = cache.get(key)
            if hit is None:
                hit = (locator.locate(px, py) + (False,) if want is None
                       else locator.locate_snapped(px, py, want, tol_m))
                cache[key] = hit
            if hit[0] is not None:
                cid[k] = hit[0]
                ocode[k] = hit[1]
                snapped[k] = hit[2]
    out[f"{prefix}court_id"] = cid
    out[f"{prefix}okres_code"] = ocode
    # <NA> where there is no court to have snapped: a row with no coordinate, or a point
    # outside every polygon, was not "not snapped" — the question did not arise for it.
    out[f"{prefix}court_snapped"] = pd.array(
        np.where(pd.isna(cid), None, snapped), dtype="boolean")
    return out

def add_settlement_courts(settlements: pd.DataFrame, districts: pd.DataFrame,
                          locator: CourtLocator, snap: bool = True,
                          tol_m: float = SNAP_TOL_M) -> pd.DataFrame:
    """Enrich the settlement crosswalk with its court district (soudní okres) by spatial join.

    Locates each geocoded settlement (``lat``/``lon``) inside the MPIDR court polygons and attaches
    ``court_id`` (Int64) plus the backbone's ``court_cs`` / ``court_de`` names. Settlements without
    coordinates — or points outside every Czech-lands court polygon — get ``<NA>``. The court is a
    *sub*-okres unit, so it is the finer geographic key the name-based okres matcher cannot supply.

    With *snap* (the default) a settlement landing just outside the polygon of its own
    ``okres_id`` is pulled back into it — see :meth:`CourtLocator.locate_snapped`. Pass
    ``snap=False`` for the raw containment answer, which is what the layer must be reduced
    to when it is used as independent evidence about the okres matcher.
    """
    out = add_court_ids(settlements, locator, lat_col="lat", lon_col="lon", prefix="",
                        okres_col="okres_id" if snap else None, tol_m=tol_m)
    out = out.drop(columns=["okres_code"])           # parent okres already carried via okres_id
    cid = districts["court_id"].astype("Int64")      # .dbf reader yields str; align to Int64 keys
    court_cs = dict(zip(cid, districts["gerichtsbezirk_cs"]))
    court_de = dict(zip(cid, districts["gerichtsbezirk_de"]))
    out["court_cs"] = out["court_id"].map(court_cs)
    out["court_de"] = out["court_id"].map(court_de)
    return out

"""
spatial.py — point-in-polygon court-district assignment from the MPIDR 1910 polygons
====================================================================================
Assigns a **court district (soudní okres / Gerichtsbezirk)** to any point given in
WGS84 lon/lat, by locating it inside the MPIDR / Rumpler-Seger 1910 court polygons
(``reference/places/mpidr/…v.1.0.shp``). This is the finer
juridical layer the name-based okres matcher (:mod:`utils.parsing.records_geo`) cannot
resolve — a court is a *sub*-okres unit, so it can only be fixed geometrically.

Why pure ``numpy`` (no geopandas / pyshp / pyproj)
--------------------------------------------------
Consistent with :mod:`utils.parsing.districts` (which hand-reads the ``.dbf``), this module
avoids a heavy geo stack:

* a **minimal ESRI shapefile reader** for polygon records (shape type 5) — record order
  aligns 1-to-1 with the ``.dbf`` rows (:func:`districts.read_dbf`), so each polygon inherits
  ``ID_1`` (=``court_id``) and its parent ``REGION``/``DISTRICT`` (=okres);
* a closed-form **ellipsoidal LAEA forward projection** (GRS80, EPSG:3035, the ``.shp`` CRS)
  to turn lon/lat into the projected metres the polygons live in;
* **ray-casting** point-in-polygon with a bounding-box prefilter.

Validation: of the settlements carrying both a court and a name-based ``okres_id``, the
court's okres agrees with the name **90.0 %** of the time on containment alone (build of
2026-09-23) and ~96 % after the D-35 near-miss repair — which agrees by construction on the
rows it snaps, so the QA gate counts those rows as the disagreements they were (audit
2026-09-22 §B9). The 68 % first measured on 2026-07-16 was **not**
structural, as this note once claimed: it was a coordinate bug — a third of geocodes came
from an unguarded unique-name fallback (audit 2026-07-16 §D2). Treat ``court_id`` as a
**complementary juridical layer**; the analysis-grade okres key remains the name-based
``okres_id``.

   Until 2026-08-05 this note also claimed that central-Prague coordinates "correctly land
   in the separate 1910 okresy Královské Vinohrady / Nusle / Vršovice, not okres Praha —
   verified". **That was wrong, and it hid a defect for three weeks.** Staré Město was

from __future__ import annotations

import struct
from pathlib import Path

import numpy as np
import pandas as pd

from utils.parsing.districts import read_dbf

__version__ = "1.1.0"

# Crown-land codes kept (Czech lands); the empire-wide .dbf is filtered to these.
_CZECH_LANDS = {"BOEHMEN", "MAEHREN", "SCHLESIEN"}

# GRS80 / EPSG:3035 (ETRS89-LAEA) parameters — read off the .prj.
_A = 6378137.0
_F = 1 / 298.257222101
_E2 = 2 * _F - _F * _F
_E = np.sqrt(_E2)
_LAT0 = np.radians(52.0)
_LON0 = np.radians(10.0)
_FE = 4321000.0
_FN = 3210000.0


# ── projection ────────────────────────────────────────────────────────────────
def laea_forward(lon, lat):
    """WGS84 lon/lat (degrees) → EPSG:3035 (ETRS89-LAEA) x/y in metres.

    Ellipsoidal Lambert Azimuthal Equal-Area, oblique aspect (Snyder 1987, eqs. 24-16 ff.),
    vectorised. Accepts scalars or arrays.
    """
    lon = np.radians(np.asarray(lon, dtype="f8"))
    lat = np.radians(np.asarray(lat, dtype="f8"))

    def _q(phi):
        s = np.sin(phi)
        return (1 - _E2) * (s / (1 - _E2 * s * s)
                            - (1 / (2 * _E)) * np.log((1 - _E * s) / (1 + _E * s)))

    qp = _q(np.pi / 2)
    rq = _A * np.sqrt(qp / 2)
    beta = np.arcsin(np.clip(_q(lat) / qp, -1, 1))
    beta0 = np.arcsin(np.clip(_q(_LAT0) / qp, -1, 1))
    m0 = np.cos(_LAT0) / np.sqrt(1 - _E2 * np.sin(_LAT0) ** 2)
    d = _A * m0 / (rq * np.cos(beta0))
    dl = lon - _LON0
    b = rq * np.sqrt(2 / (1 + np.sin(beta0) * np.sin(beta)
                          + np.cos(beta0) * np.cos(beta) * np.cos(dl)))
    x = b * d * np.cos(beta) * np.sin(dl)
    y = (b / d) * (np.cos(beta0) * np.sin(beta)
                   - np.sin(beta0) * np.cos(beta) * np.cos(dl))
    return _FE + x, _FN + y


# ── minimal ESRI .shp polygon reader ────────────────────────────────────────────
def read_polygons(shp_path) -> list[list[np.ndarray]]:
    """Read an ESRI ``.shp`` into one entry per record (record order = ``.dbf`` row order).

    Each entry is a list of rings; each ring is an ``(N, 2)`` float array of projected
    coordinates. Non-polygon / null records yield an empty list.
    """
    raw = Path(shp_path).read_bytes()
    pos, n = 100, len(raw)                       # skip the 100-byte file header
    recs: list[list[np.ndarray]] = []
    while pos < n:
        _rec_no, clen = struct.unpack(">ii", raw[pos:pos + 8])
        pos += 8
        nxt = pos + clen * 2                      # content length is in 16-bit words
        shape_type = struct.unpack("<i", raw[pos:pos + 4])[0]
        if shape_type != 5:                       # 5 = polygon; 0 = null / other
            recs.append([])
            pos = nxt
            continue
        p = pos + 4 + 32                          # skip shape type (4) + bbox (4 doubles)
        n_parts, n_pts = struct.unpack("<ii", raw[p:p + 8])
        p += 8
        parts = struct.unpack("<%di" % n_parts, raw[p:p + 4 * n_parts])
        p += 4 * n_parts
        pts = np.frombuffer(raw[p:p + 16 * n_pts], dtype="<f8").reshape(n_pts, 2)
        idx = list(parts) + [n_pts]
        recs.append([pts[a:b] for a, b in zip(idx[:-1], idx[1:])])
        pos = nxt
    return recs


def _point_in_ring(x: float, y: float, ring: np.ndarray) -> bool:
    """Ray-casting even-odd test for a single ring."""
    inside = False
    n = len(ring)
    j = n - 1
    for i in range(n):
        xi, yi = ring[i]
        xj, yj = ring[j]
        if ((yi > y) != (yj > y)) and (x < (xj - xi) * (y - yi) / (yj - yi) + xi):
            inside = not inside
        j = i
    return inside


def _ring_min_distance(x: float, y: float, ring: np.ndarray) -> float:
    """Shortest distance in metres from a point to a ring's edge (not its interior)."""
    a, b = ring[:-1], ring[1:]
    d = b - a
    ll = (d ** 2).sum(1)
    ll[ll == 0] = 1e-12
    t = np.clip(((x - a[:, 0]) * d[:, 0] + (y - a[:, 1]) * d[:, 1]) / ll, 0.0, 1.0)
    cx = a[:, 0] + t * d[:, 0]
    cy = a[:, 1] + t * d[:, 1]
    return float(np.sqrt((x - cx) ** 2 + (y - cy) ** 2).min())


# How far a point may sit outside the polygon of its own (name-derived) okres and still be
# snapped back into it. The MPIDR boundaries are an empire-wide generalisation, so a city
# outline is accurate to something like a kilometre — which is enough to put a genuine
# central-city coordinate on the wrong side of its own border.
#
# Chosen from the measured distribution rather than from taste. Of 5,660 geocoded
# settlements, 624 (11.0 %) locate into a court belonging to a *different* okres than their
# name; their distance to the nearest polygon of their own okres has median 765 m and runs
# out to 318 km. 1,000 m captures 382 of them and stops well below the tail, where the
# disagreement is a real one — two different places — and must be left alone to say so.
SNAP_TOL_M = 1000.0

# ── court locator ───────────────────────────────────────────────────────────────
class CourtLocator:
    """Locate WGS84 points inside the MPIDR Czech-lands court polygons.

    Builds an in-memory list of ``(court_id, okres_code, rings, bbox)`` from the aligned
    ``.dbf`` / ``.shp`` pair, filtered to the Czech crown lands. :meth:`locate` returns the
    ``(court_id, okres_code)`` of the polygon containing a point, or ``(None, None)``.
    """

    def __init__(self, dbf_path, shp_path, lands: set[str] = _CZECH_LANDS):
        dbf = read_dbf(dbf_path)
        polys = read_polygons(shp_path)
        if len(dbf) != len(polys):
            raise ValueError(f".dbf ({len(dbf)}) and .shp ({len(polys)}) record counts differ; "
                             "cannot align attributes to geometry.")
        self.courts: list[tuple] = []
        self.by_okres: dict[int, list[tuple]] = {}
        for rec, rings in zip(dbf, polys):
            if rec.get("LAND") not in lands or not rings:
                continue
            allpts = np.vstack(rings)
            bbox = (allpts[:, 0].min(), allpts[:, 1].min(),
                    allpts[:, 0].max(), allpts[:, 1].max())
            code = f"{rec['REGION']}-{rec['DISTRICT']}"
            entry = (int(rec["ID_1"]), code, rings, bbox)
            self.courts.append(entry)
            oid = int(rec["REGION"]) * 1000 + int(rec["DISTRICT"])
            self.by_okres.setdefault(oid, []).append(entry)

    def locate(self, px: float, py: float) -> tuple:
        """Return ``(court_id, okres_code)`` for a projected point, else ``(None, None)``.

        Containment is **even-odd over all rings** (odd ring count = inside): an ESRI
        polygon's holes are extra rings, so a point inside an enclave (a city court cut
        out of the surrounding rural court) tests inside the outer ring *and* the hole —
        even parity, correctly outside. A plain ``any()`` would let whichever polygon
        comes first in file order claim enclave points.
        """
        for court_id, okres_code, rings, (x0, y0, x1, y1) in self.courts:
            if not (x0 <= px <= x1 and y0 <= py <= y1):
                continue
            if sum(_point_in_ring(px, py, r) for r in rings) % 2 == 1:
                return court_id, okres_code
        return None, None

    def locate_snapped(self, px: float, py: float, prefer_okres: int | None,
                       tol_m: float = SNAP_TOL_M) -> tuple:
        """:meth:`locate`, but a near miss against *prefer_okres* is pulled back into it.

        Returns ``(court_id, okres_code, snapped)``.

        The MPIDR outlines are an empire-wide generalisation, so a city border can sit a
        kilometre from where it ran. Prague is the case that made this necessary: the
        polygon labelled *Prag/Praha St.* is the right size (20.8 km² against the city's
        ~21 km²) but its eastern edge is drawn ~500 m too far west, so the single Wikidata
        coordinate every ``Praha`` birth carries — Old Town Square, 50.0875 N 14.4214 E,
        unambiguously inside the 1910 city — fell into neighbouring Královské Vinohrady.
        All 2,691 court-placed Prague births went there and the Praha court polygon
        received **none**.

        The repair only fires where the name evidence and the geometry disagree *and* the
        point is within ``tol_m`` of the named okres — the signature of a boundary drawn
        slightly wrong. A disagreement further out is a disagreement about which place this
        is, not about where a line runs, and is left standing so the layer keeps its value
        as a cross-check. Snapped rows are flagged, so any use of the court layer as
        independent evidence can drop them.
        """
        court_id, okres_code = self.locate(px, py)
        if prefer_okres is None or pd.isna(prefer_okres):
            return court_id, okres_code, False
        prefer_okres = int(prefer_okres)
        if okres_code is not None:
            r, d = okres_code.split("-")
            if int(r) * 1000 + int(d) == prefer_okres:
                return court_id, okres_code, False        # geometry already agrees

        best, best_d = None, tol_m
        for entry in self.by_okres.get(prefer_okres, []):
            _cid, _code, rings, (x0, y0, x1, y1) = entry
            if not (x0 - tol_m <= px <= x1 + tol_m and y0 - tol_m <= py <= y1 + tol_m):
                continue
            dist = min(_ring_min_distance(px, py, r) for r in rings)
            if dist <= best_d:
                best, best_d = entry, dist
        if best is None:
            return court_id, okres_code, False
        return best[0], best[1], True


def add_court_ids(df: pd.DataFrame, locator: CourtLocator,
                  lat_col: str = "lat", lon_col: str = "lon",
                  prefix: str = "", okres_col: str | None = None,
                  tol_m: float = SNAP_TOL_M) -> pd.DataFrame:
    """Append ``{prefix}court_id`` (Int64) and ``{prefix}okres_code`` from a spatial lookup.

    Rows with a missing coordinate — or points outside every Czech-lands court polygon —
    get ``<NA>``. Distinct coordinate pairs are located once and broadcast.

    Pass *okres_col* — the row's own name-derived okres id — to enable the near-miss repair
    described in :meth:`CourtLocator.locate_snapped`; a boolean ``{prefix}court_snapped``
    then records which rows it moved. Without it the lookup is pure containment, as before.
    """
    out = df.copy()
    has = out[lat_col].notna() & out[lon_col].notna()
    cid = pd.array([pd.NA] * len(out), dtype="Int64")
    ocode: list[object] = [pd.NA] * len(out)
    snapped = np.zeros(len(out), bool)
    prefer = out[okres_col].to_numpy() if okres_col and okres_col in out.columns else None
    if has.any():
        sub = out.loc[has, [lon_col, lat_col]]
        xs, ys = laea_forward(sub[lon_col].to_numpy(), sub[lat_col].to_numpy())
        # cache by rounded coordinate *and* preferred okres: the same point can legitimately
        # resolve differently for two settlements whose names put them in different okresy
        cache: dict[tuple, tuple] = {}
        pos = np.flatnonzero(has.to_numpy())
        for k, px, py in zip(pos, xs, ys):
            want = None if prefer is None or pd.isna(prefer[k]) else int(prefer[k])
            key = (round(float(px), 1), round(float(py), 1), want)
            hit = cache.get(key)
            if hit is None:
                hit = (locator.locate(px, py) + (False,) if want is None
                       else locator.locate_snapped(px, py, want, tol_m))
                cache[key] = hit
            if hit[0] is not None:
                cid[k] = hit[0]
                ocode[k] = hit[1]
                snapped[k] = hit[2]
    out[f"{prefix}court_id"] = cid
    out[f"{prefix}okres_code"] = ocode
    # <NA> where there is no court to have snapped: a row with no coordinate, or a point
    # outside every polygon, was not "not snapped" — the question did not arise for it.
    out[f"{prefix}court_snapped"] = pd.array(
        np.where(pd.isna(cid), None, snapped), dtype="boolean")
    return out


def add_settlement_courts(settlements: pd.DataFrame, districts: pd.DataFrame,
                          locator: CourtLocator, snap: bool = True,
                          tol_m: float = SNAP_TOL_M) -> pd.DataFrame:
    """Enrich the settlement crosswalk with its court district (soudní okres) by spatial join.

    Locates each geocoded settlement (``lat``/``lon``) inside the MPIDR court polygons and attaches
    ``court_id`` (Int64) plus the backbone's ``court_cs`` / ``court_de`` names. Settlements without
    coordinates — or points outside every Czech-lands court polygon — get ``<NA>``. The court is a
    *sub*-okres unit, so it is the finer geographic key the name-based okres matcher cannot supply.

    With *snap* (the default) a settlement landing just outside the polygon of its own
    ``okres_id`` is pulled back into it — see :meth:`CourtLocator.locate_snapped`. Pass
    ``snap=False`` for the raw containment answer, which is what the layer must be reduced
    to when it is used as independent evidence about the okres matcher.
    """
    out = add_court_ids(settlements, locator, lat_col="lat", lon_col="lon", prefix="",
                        okres_col="okres_id" if snap else None, tol_m=tol_m)
    out = out.drop(columns=["okres_code"])           # parent okres already carried via okres_id
    cid = districts["court_id"].astype("Int64")      # .dbf reader yields str; align to Int64 keys
    court_cs = dict(zip(cid, districts["gerichtsbezirk_cs"]))
    court_de = dict(zip(cid, districts["gerichtsbezirk_de"]))
    out["court_cs"] = out["court_id"].map(court_cs)
    out["court_de"] = out["court_id"].map(court_de)
    return out


def settlement_court_report(settlements: pd.DataFrame) -> None:
    """Print court-district fill rate on the enriched settlement crosswalk."""
    n = len(settlements)
    geo = settlements["lat"].notna().sum() if "lat" in settlements.columns else 0
    has = settlements["court_id"].notna().sum()
    print(f"Settlement court districts  (settlements = {n:,})")
    print(f"  geocoded (lat/lon):   {geo:,}  ({geo/n*100:.1f}%)")
    print(f"  located in a court:   {has:,}  ({has/n*100:.1f}%"
          + (f", {has/geo*100:.1f}% of geocoded)" if geo else ")"))
